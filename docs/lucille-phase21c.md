No merge, release, installation or general activation. This is a **partial result**: real models/transport/GUI/persistence work in isolated tests, but LLM-only extraction and real retrieval do not meet the predeclared quality gates.

Acceptance is in `lucille-phase21c-acceptance.md`. Development smoke prompts preceded the freeze. The original frozen source hash is retained, and the final production-contract fixture records unchanged native algorithm hashes and the exact normalized prompt hash. Later transport-only pin verification/status labels do not change extraction semantics or repair model proposals. No algorithm/prompt tuning followed final scores.

Final corpus `phase21c-real-final-v1`: **38 interactions, 23 expected claims**, SHA-256 `ac2f1730a9dc840376d64fb601878b6a2d4ced925f5f12fbf90bbce799edebdc`. Human-defined typed gold, no exact text overlap with historical fixtures. One real response per input is fed unchanged into canonical LLM and hybrid ingestion; rules see the same text. Candidate and active records are scored, with explicit scope/project checks and one-to-one typed specified gold fields. This measures accepted extraction, not automatic promotion of all records. Gold uses property prefixes for content-addressed keys and does not specify every optional textual field. The implementer authored the set after freezing; this is not a blinded external evaluation.

## Real embeddings and retrieval

Actual Nomic vectors use `search_document: ` and `search_query: `, native mean pooling, full-dimensional layer normalization then L2. The positive scalar layer-norm denominator cancels in final L2, so the broker centers and L2-normalizes the actual raw vector; it does not fabricate embeddings. All 768 entries are finite, norms within .001; repeat max component difference was 0 with tolerance 1e-5. Thirty-three measured embedding calls had P50/P95 about .059/.082s. Native bridge roundtrip P50/P95 .035/.040s includes process startup/SQLite; it is not a pure database-engine timing.

Retrieval corpus `phase21c-real-retrieval-v1`: eight synthetic manually approved facts, 24 identical queries (8 lexical, 8 paraphrases, 8 irrelevant), SHA-256 `989ffeaf0e954e8cb181546d96d27a5f4bedd52cd1b778172f65e6fdf79b22f7`. This isolates retrieval from extraction. Default semantic cutoff .78 and hybrid weights .7/.3 were fixed before any final embedding. No tuning or relabelling followed these failures.

| Retrieval | TP | FP | Missed | Precision | Recall | Wilson95 recall |
|---|---:|---:|---:|---:|---:|---|
| FTS5 | 9 | 4 | 7 | .6923 | .5625 | [.332,.769] |
| Real Nomic | 5 | 0 | 11 | 1.0 | .3125 | [.142,.556] |

All three fail the quality gates. FTS5/hybrid precision Wilson95 is [.424,.873]; real semantic precision [.566,1]. Small handcrafted data/intervals are descriptive, not population guarantees. Semantic-only returned no correct paraphrase result in its eight paraphrase queries at the frozen cutoff. Hybrid did not improve on FTS here. All eight wholly irrelevant queries returned empty; the four FPs were additional wrong records in other queries. Project fencing and real-vector deletion after reopening passed. A separate lifecycle check reused actual previously generated Nomic vectors (no new inference): editing/reapproval excluded the old version, stale writes failed and canonical deletion physically purged the retained old vector. Invalidation on edit is logical/versioned, not immediate physical removal. An initial assertion incorrectly required immediate removal; the canonical version filter and physical deletion were then tested explicitly. No ranking/data/algorithm was changed. There is no claim of semantic/hybrid superiority or successful general semantic recovery.

## Isolated broker, GUI and persistence

`lucille-real-broker.py` verifies the actual model files against pinned SHA-256, copied executable hash, and a live owned PID/path/creation-time manifest before/after calls; file size/mtime changes invalidate the session. The QA Vite configuration embeds only the public pin from a marked checkout-owned root. Advertised model names alone remain insufficient; simulation cannot be promoted by a server's own claim. Normal builds retain the previous simulated-only guard and disabled/rules defaults. SQLite's existing `transport_verified=false` field remains a non-attestation of a portable database; the **live QA broker/client** provide the additional independent file/process checks, not a claim persisted by importing an index.

The broker adapts actual bounded non-streaming Gemma replies into SSE for the application, preserving text/finish reason/usage; this buffers output rather than measuring native streaming behavior. After cancellation an already issued bounded model call may finish, but revoked leases cannot write. This is not immediate GPU preemption or production streaming/cancellation approval.

Actual full-app Chat/Agent/Code composers/hooks and native canonical SQLite passed: shared synthetic identity, LLM coffee preference, hybrid PC16→32 with work-laptop8 unchanged, reviewed preference withdrawal and history, real Nomic index, native host-only restart, bindings/index/identity persistence, deletion and old-interaction replay fencing. Real in-flight cancellation left records unchanged and purged source. Stopping only the owned Nomic made the UI show lexical fallback; real Gemma answered an unrelated question without retrieved memory. Screenshots were taken through the exclusive QA WebView, not the global desktop capture service. This does not claim to repair Codex's general screenshot issue.
