# Phase 2.1C predeclared acceptance

Freeze before final evaluation. Each extraction mode independently requires precision >= .95 and recall >= .80, zero critical unsafe writes, scope errors and identity/permission changes. Same frozen inputs for rules, real LLM and real hybrid. Native deterministic validators/policy/SQLite remain authoritative. No dataset edits or production tuning after final results; a new evaluation is required if changes are made.

Retrieval on the same data: FTS5, real Nomic and hybrid, precision >= .95, recall >= .80; unrelated queries should return empty. Preserve default .78 semantic threshold and .7/.3 fusion, scope/state/delete/expiry/version filters. Report actual failures and small-sample limitations. Hypotheses/corrections/candidate review are not automatic facts. Real extraction cannot be approved based on hybrid compensation.

Gemma: context 65536, one slot, temperature0, max768 output tokens, no reasoning; bounded calls and resource monitoring. No extra models concurrently unless measured headroom is sufficient. Pressure: <512MiB physical available or <1GiB commit headroom for three samples stops only the owned test process. High usage alone is not a failure. No operational process/configuration changes. Ownership: retained handle + PID/image/creation-time manifest checked before shutdown.

Final corpus authored after this production/prompt freeze, sealed with SHA-256 before any final inference. Human-defined typed gold is not generated by rules. Development smoke prompts and all historical data are regression-only. Per-mode/category counts and errors must remain visible. Samples are small and authored by the implementer, not a blinded third-party evaluation.
